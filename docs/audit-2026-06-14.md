# Codebase audit — 2026-06-14

Staleness and consistency audit of the whole repository — engine package, docs,
and the strategy notebooks. Unlike the two prior passes
([audit-2026-06-04.md](audit-2026-06-04.md) and
[audit-2026-06-13.md](audit-2026-06-13.md), which hunted correctness bugs), this
one is scoped to drift: stale / inert / dead / unused code and prose, and
inconsistencies where a comment, doc, or name disagrees with the code or with
another file.

This is a review-only pass — no code was changed. No correctness or look-ahead
issues surfaced; the load-bearing core path that the prior audits hardened still
holds. Every finding below clusters in documentation, comments, and notebook
hygiene.

---

## Method

The audit fanned out across 23 areas (12 engine subsystems, 3 doc groups, 8
notebook groups). Each area was read independently, then every raw finding was
handed to a separate adversarial verifier told to refute it by re-reading the
source — the same one-skeptic-per-finding discipline as the 2026-06-13 pass.
70 raw findings were produced; 45 survived verification and 25 were refuted as
false positives (listed in section 4). The surviving findings were then
deduplicated and the most actionable were independently re-checked against source
by hand. File:line references are current as of this audit; a few may drift again
as code shifts, so re-confirm at edit time.

The dominant theme: the g_* strategy family (g_bounce / g_breakout /
g_breakout_false / g_range), added in commit a4c77a0, is fully wired into the
engine (StrategyName enum, strategies package, CLI dispatch, the G*Params classes
at [strategy_configurator.py:349-426](../engine/strategy_configurator.py#L349))
but is invisible in every piece of documentation — the strategy count, the family
prose, the CLI tables, and the comparison notebook all predate it.

## 1. Summary

- Total actionable findings: 33 (deduplicated from 45 verified).
- By severity: High 0 — Medium 4 — Low 29.
- Themes:
  1. The g_* strategy family is undocumented everywhere — counts say "20
     strategies" when there are 24, and the four g_* names are absent from every
     list.
  2. Stale comments and docstrings across the engine describe a pre-rename /
     pre-wiring world (planned-but-built strategies, "they'll replace", a
     pre-rename level_breakout reference).
  3. A handful of genuinely dead symbols (an unused enum, an unused import, two
     never-called members).
  4. The two dated audit logs carry a dead file link and one factually wrong
     inventory — historical-log noise, but misleading if re-read.
  5. Notebook hygiene — typos, unused imports, and TOC anchor drift.

## 2. Medium

### M1. Strategy count says 20 but there are 24; the g_* family is undocumented
- [CLAUDE.md:40](../CLAUDE.md#L40) — "20 strategies"; the StrategyName enum has
  24 members. The same sentence claims the level family "has room to grow
  (level_bounce, level_retest)", but g_bounce is the shipped level-bounce
  strategy.
- [CLAUDE.md:68](../CLAUDE.md#L68) — the per-family Params-class list names eleven
  classes and omits the four G*Params subclasses (GBounceParams / GBreakoutParams
  / GBreakoutFalseParams / GRangeParams). They subclass LevelParams, so at minimum
  the prose should name the g_* family.
- [docs/DEVELOPMENT.md:51](DEVELOPMENT.md#L51) — "# 20 strategies" in the tree
  comment, and the --strategy table at
  [DEVELOPMENT.md:136](DEVELOPMENT.md#L136) lists 20 names, omitting g_bounce,
  g_breakout, g_breakout_false, g_range.
- Fix: bump the counts to 24, document the g_* family in CLAUDE.md, add the four
  names to the DEVELOPMENT.md --strategy table, and rewrite the "room to grow"
  sentence (level_retest may remain a possible future enhancement; level_bounce
  is done).

### M2. DEVELOPMENT.md CLI flags table omits every trade-config option
- [docs/DEVELOPMENT.md:134-145](DEVELOPMENT.md#L134) lists only the 10 original
  flags. The trade-config flags added in the config split — --fee-bps,
  --slippage-bps, --direction, --position-size-bps, --leverage, --sizing-mode,
  --risk-per-trade-bps, --max-daily-loss-bps, --max-holding-bars, --exit-preset,
  --initial-equity — are all live in [cli.py](../engine/cli.py) but absent from
  the table.
- Fix: add a row per missing flag with its default and a one-line description.

### M3. levels.ipynb TOC anchors use wrong case, breaking navigation
- [strategy_notebooks/levels.ipynb](../strategy_notebooks/levels.ipynb) — the
  table-of-contents links use capitalized anchors (Configuration, Pivot-level,
  Levels-with-EMAs) while every other notebook uses lowercase-hyphenated slugs.
  It also relies on auto-numbered duplicate anchors (Parameters-1 / Parameters-2)
  for repeated subsection names, which no other notebook does.
- Fix: lowercase and hyphenate the anchor links, and give the repeated
  subsections unique headings (Pivot parameters / Cluster parameters / Touch
  parameters).

### M4. CLAUDE.md deep-link line anchors have drifted (needs human check)
- Several CLAUDE.md markdown links carry a #Lnn anchor that is a few lines off the
  current definition after code shifted: PositionState, Trade.peak_price,
  LiveEngine._tick(), LiveRecords. Clicking lands near, but not on, the target.
- Fix: re-resolve each anchor against the current file and update. Re-confirm at
  edit time, since these shift whenever the referenced files change.

  define their own buffer/tolerance params. Rewrite so the base docstring stops

- [strategy_configurator.py:242](../engine/strategy_configurator.py#L242) — the
  LevelParams docstring says all three detectors read the shared level_* knobs

- [strategy_configurator.py:200-201](../engine/strategy_configurator.py#L200) —

  Qualify it.
- [supertrend_inv.py:64](../engine/strategies/supertrend_inv.py#L64) — the inline

- [core.py:144](../engine/core.py#L144) — the equity-fields comment says they are

  populates notional / pnl_currency / equity_after as trades close. Add the live

- [live.py:99-111](../engine/live.py#L99) — _seed_state_policy's docstring

- [visualization.py:130](../engine/visualization.py#L130) — build_chart's Args

## 6. Resolution (applied 2026-06-14)

All 33 findings were applied the same day; `pytest engine/tests/` → 355 passing,
and `pyflakes engine/` is clean.

- M1 / M2 — CLAUDE.md and DEVELOPMENT.md now say 24 strategies, document the g_*
  family, and DEVELOPMENT.md's CLI table lists every flag (data, output, and the
  full TradingConfig group). M4 — the CLAUDE.md line anchors were re-resolved
  against current source (PositionState L159, LiveEngine._tick L203, LiveRecords
  L63; Trade.peak_price L133 became correct after the core.py line shift).
- 3a — RunMode, the unused `timezone` import, `_StreakTracker.in_progress_start`,
  `LiveRecords.load_trade_history` (and its now-orphaned `ExitReason` import), and
  the redundant `if self._state` guard were removed. 3b — the stale comments /
  docstrings were corrected; `LiveEngine` now registers shutdown handlers in a
  dedicated `_register_shutdown_handlers()` rather than inside `_seed_state_policy`.
- M3 — levels.ipynb got explicit unique `<a id>` anchors on its pivot/cluster/touch
  sections + subsections and a rewritten lowercase TOC (all 26 links resolve). 3d
  — intro.ipynb typos fixed; swing_ml.ipynb unused imports removed;
  strategy_comparison.ipynb now runs all 23 non-ML strategies (was 15) with a
  corrected caveat.
- 3c — the historical audit logs and level-detectors-plan were annotated (not
  rewritten) for the deleted `engine/fetcher.py` (now `engine/providers/bybit.py`),
  the inaccurate §4a field names, and the RunMode removal. 3e — `grid_search`'s
  lean column set is now documented inline as intentional.
- Finding #27 (g_bounce/g_range "missing" Configuration anchors) was a no-op on
  inspection: plain Configuration headers with lowercase auto-slug links are the
  repo-wide convention (ema_rsi, super_trend, all standard notebooks), and both
  notebooks' TOC links already resolve — adding anchors would have introduced an
  inconsistency, not removed one.
- Additionally, four pre-existing dead items that the 2026-06-04 §4 inventory
  listed but were never cleaned (the unused `alpha` local in `adx()`, and unused
  `ExitReason` / `VwapParams` / `SwingParams` imports in impulse_flag / vwap_bands
  / swing_flip) were removed in the same sweep, leaving `pyflakes engine/` clean.
