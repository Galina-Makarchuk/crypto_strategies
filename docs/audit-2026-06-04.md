## 2. DEFERRED correctness finding — #7 ML training-notebook leakage

**Not** auto-applied: it's a research-pipeline change woven across several
training cells that needs an expensive multi-year re-run to validate. It must be
done deliberately, with your sign-off.

- **Files:** [strategy_notebooks/swing_ml.ipynb](../strategy_notebooks/swing_ml.ipynb),
  [strategy_notebooks/swing_ml_t3.ipynb](../strategy_notebooks/swing_ml_t3.ipynb)
- **Problem:** `calibrate_threshold(df)` and `oracle_swing_labels(df)` run on the
  **full** history, then the result is split with `PurgedKFold`. This leaks
  test-fold structure into the train labels (via the detector's forward-stateful
  confirmation) and fits a single global threshold across all folds — exactly
  what [engine/ml/labels.py](../engine/ml/labels.py) (lines ~50-53) warns against.
  Result: optimistic OOS metrics.
- **Fix:** move threshold calibration + oracle-label generation **inside** the CV
  loop, per train fold (train slice + embargo only), then predict OOS on the test
  slice. Re-train + regenerate the model artifact and OOS probabilities.
- **Note:** the engine-side OOS backtest path (`SwingMLStrategy(..., require_model=False)`)
  is already correct — the leakage is purely in how the notebook produces the
  probabilities it injects.

## 3. Residual notes from the fixes (follow-up)

- **Live structural take-profit not re-armed across ticks.** Fix #1 removes the
  catastrophic 0.0 exit, but in **live** mode the structural strategies' target
  (`ref_target`) is still lost after the entry tick because `prepare()` zeroes the
  per-trade state every tick. So in live the take-profit won't fire — the position
  rides on its (now-persisted) stop / signal exits. Deeper fix: re-derive the
  active target for an open position each tick, persist it, or stop resetting
  per-trade exit state in `prepare()` while a position is open.
- **Live cross-bar strategy state is wiped each tick.** `order_block._obs`,
  `impulse_flag`/`exhaustion` setups accumulate across bars, but `prepare()` rebuilds
  them from scratch every live tick (and `on_bar` runs only on the last bar), so
  these strategies effectively can't open new structural trades in live mode.
  Architectural: the live engine needs to persist strategy state or run `prepare()`
  incrementally. (Backtests are unaffected — `prepare()` runs once there.)
- **Equity floor semantics.** Fix #5 models a blown account at 0. If you want
  margin-call / liquidation semantics (close at maintenance margin), that's a
  further enhancement.
